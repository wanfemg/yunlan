# 站长账号登录

浏览器先显示独立账号密码登录页，登录成功后才加载仪表板和各业务模块。
圈钱中心沿用同一站长会话，不设置第二套财务口令。

## 正式模式

将 `NEWAPI_UPSTREAM` 设置为实际 NewAPI 根地址，使用该实例现有站长账号密码登录。
程序通过 NewAPI 官方登录流程核对身份，仅允许启用的站长角色进入后台。
不在本项目复制、修改或保存 NewAPI 用户密码，也不修改 NewAPI 源码。

`NEWAPI_ADMIN_TOKEN` 和 `NEWAPI_ADMIN_USER_ID` 用于已有管理桥操作，
不作为网页登录的前置凭据。`ADMIN_TOKEN` 仍供进程内调度和明确的程序 API 调用，
人类登录界面不再要求输入它。

NewAPI 已启用的二次验证继续生效，可填写动态验证码或备用恢复码。
只提供 Passkey 等绑定原站点的认证方式时，本项目不会跳过验证；
须在原 NewAPI 实例配置可用的二次验证方式。
源站启用 Turnstile 时，登录页显示官方验证码组件，完成后才提交登录；
站长后台域名需要在该验证码站点密钥的允许域名中。

缺少 NewAPI 地址、上游暂时不可达、账号权限不足或验证未完成时，不创建已登录会话。
正式模式不会回退到演示账号。

## 本地演示

运行 `Start-Demo.ps1` 后访问 `http://127.0.0.1:5173/`：

- 账号：`root`
- 密码：`123456`

这套固定账号只存在于演示模式。演示预览可先登录，再到系统连接页保存正式接入配置。
随后使用集成启动器进入真实模式，登录改用实际 NewAPI 站长账号。

## 会话与退出

浏览器仅保存 HttpOnly、SameSite=Strict 的随机会话 Cookie，写操作携带会话 CSRF
凭据；财务 iframe、批量管理和数据库上传共用这套校验。
上游账号权限和会话状态按短缓存重新核对，账号失效后停止访问。

会话与上游凭据保存在后台进程内存，进程重启后需重新登录。
退出登录调用后台清除会话，成功后才切换回登录页。

`SITEADMIN_COOKIE_SECURE` 支持 `auto`、`true`、`false`。
本地 HTTP 演示固定使用 `false`；正式 HTTPS 反代使用 `true`，
并通过 HTTPS 访问页面。`auto` 根据实际 TLS 或受信任的本机 HTTPS 转发判断。
